# CSS Audit — Style Reference (2026-04-27)

**Target:** `style.css` (1591 lines), `index.html` (805 lines, where supporting CSS)
**Spec:** `docs/specs/2026-04-27-css-audit-design.md`
**Browser-support floor:** Baseline Widely Available
**Triage:** Critical / Recommended / Polish (see spec §2)

## Executive summary

- **Findings: 3 Critical · 13 Recommended · 13 Polish (29 total)**

Headline observations:

- **Two real value drifts between tokens and the specimen-as-source-of-truth.** `--pan-lerp` is `0.02` in CSS but the §1.8 Motion specimen displays `0.08`; `--focus-fade` is `200ms` in CSS but the same specimen captions `360ms`. Per CLAUDE.md the specimen *is* the system, so the disagreement violates the file's own foundational invariant. Both need a Kees-call before fixing — the runtime feel is materially different at each value.
- **The runtime/specimen split is enforced by source order and a 17-line banner comment, not by the cascade itself.** A single `@layer runtime, specimen;` declaration would encode the architectural intent in CSS — a textbook fit and the file's highest-payoff modern-CSS adoption.
- **The charcoal alpha ladder is documented as a brand system in §1.4 but implemented as 34 `rgba(26, 26, 26, …)` literals.** Same pattern at smaller scale for blue (10) and field (5). The single-source-of-truth claim the file's banners make isn't actually present; `color-mix(in srgb, var(--charcoal) 65%, transparent)` derives every alpha from one source token.
- **Specimen-block source order doesn't match HTML render order.** HTML renders 00 → 1.1 → 1.2 → 1.3 → … → 99; CSS authors them Masthead → Principles → Color → Type → Spacing → Motion → Mobile-cell → Elevation → Colophon → Grid → Identity → Anatomy template → Overlays. Reordering is safe (specimens don't depend on each other) and tightens navigation.
- **The file lacks a top-of-file orientation for a 1591-line single-file system.** Five lines of brand attribution then straight into the Grid `:root`; no section index, no runtime/specimen pointer, no banner-style guide. A 15-line preamble would orient an editor in seconds.

## Findings

### Critical

#### C-1 · `--pan-lerp` token value disagrees with the specimen's documented value

- **Axis:** §1 (Token discipline)
- **Location:** `style.css:54` (token), `index.html:424–425` (specimen)
- **Observation:** CSS defines `--pan-lerp: 0.02;`. The §1.8 Motion specimen displays `0.08` as the rendered value AND in the caption (`--pan-lerp / 0.08 — per-frame damping factor for pan velocity (JS)`).
- **Why it matters:** The style-reference's foundational invariant per CLAUDE.md is "the specimen page at index.html *is* the system; if it's not visible on the page, it's not part of the brand." The specimen and the token must agree by construction. They don't. Whichever value is wrong is silently misleading any reader treating the file as a system of record.
- **Recommendation:** **Tension-surface gate triggers.** Two valid recommendations exist with materially different aesthetic outcomes — `0.02` is heavier/laggier; `0.08` is more responsive. Surface to Kees: which is canonical? Then update the disagreeing surface. The bird-portfolio runtime is downstream and out of scope per CLAUDE.md isolation rule, so the choice is between this file's two surfaces.
- **See also:** §6 (this is also a comment/spec claim now false; the token-discipline lens leads).

#### C-2 · `--focus-fade` token value disagrees with the specimen's documented value

- **Axis:** §1 (Token discipline)
- **Location:** `style.css:55` (token), `index.html:429` (specimen caption)
- **Observation:** CSS defines `--focus-fade: 200ms;`. The §1.8 Motion specimen caption reads `--focus-fade / 360ms`. Note that `--focus-fade` actively drives runtime transitions on `.photo` (`style.css:143–146`), so the value is load-bearing.
- **Why it matters:** Same as C-1. Additionally, because `--focus-fade` is consumed (unlike `--pan-lerp`, which is a runtime-JS value displayed for documentation only), the cascading effect of changing it is real: every `.photo` transition retimes.
- **Recommendation:** **Tension-surface gate triggers.** Surface to Kees — `200ms` is snappy, `360ms` is cinematic. Then align the disagreeing surface.
- **See also:** §6.

#### C-3 · Banner "Grid ruleset — first specimen on the page" is stale

- **Axis:** §6 (Comment signal-to-noise)
- **Location:** `style.css:1130–1132`
- **Observation:** The banner reads "Grid ruleset — *first specimen on the page*". By page render order (the order an editor sees as they scroll the spec), Grid is the 4th section: 00 Masthead, 1.1 Principles, 1.2 Identity, 1.3 Grid. By CSS source order, the Grid ruleset is the 11th specimen-cluster (Masthead → Principles → Color → Photo treatment → Typography → Spacing → Motion → Mobile-cell → Elevation → Colophon → Grid). Neither reading supports "first."
- **Why it matters:** Per spec §2 Critical: "code contradicts its own comment/intent, or a comment's claim is now false." A reader trusts banner comments to orient them; this one misorients.
- **Recommendation:** Replace with an accurate header — e.g., "Grid ruleset — §1.3 specimen — token chips + page-anatomy diagram." Pairs with R-7 (specimen reorder) — once specimens are in section order, relative-position framing in banner comments becomes safer.
- **See also:** §2 (file organization).

### Recommended

#### R-1 · Adopt `@layer` to encode the cascade architecture

- **Axis:** §7 (Modern CSS leverage)
- **Location:** Anchor at `style.css:457–473` (the END RUNTIME · BEGIN SPECIMEN banner); declaration would land at the top of the file
- **Observation:** The runtime/specimen split is currently maintained by (a) source order, (b) the 17-line banner comment at L457–473, and (c) human convention. The CSS itself doesn't enforce the split — a specimen rule placed before runtime via accidental edit silently wins. The `html, body` specimen override at L475–480 (`overflow: auto; height: auto;`) currently relies on source-order specificity to defeat the runtime's `overflow: hidden`.
- **Why it matters:** Cascade Layers is Baseline Widely Available; the file is a textbook fit. The comment at L466–469 ("the specimen may consume the runtime; the runtime may not reference the specimen — keep the boundary one-way") is exactly the contract `@layer` makes structural. Per spec §1 axis-7 row, this is the headline modern-CSS adoption opportunity in the file.
- **Recommendation:** Declare `@layer reset, tokens, runtime, specimen, debug;` near the top of the file (after the preamble suggested in R-2). Wrap existing rule blocks accordingly. The `?grid` debug overlay (L1192–1239) goes in `debug`; the two `:root` blocks go in `tokens`; `*`/`html, body` go in `reset`. No behavioral change at parse time; the architectural intent moves from human-readable convention to CSS-encoded fact.
- **See also:** R-2 (preamble references the layers), R-7 (layers make specimen reorder safe), C-3 (banner-style intent expressed as code).

#### R-2 · File preamble missing — add 10–30 line top-of-file map

- **Axis:** §2 (File organization & narrative)
- **Location:** `style.css:1–13`
- **Observation:** The file opens with a 5-line attribution banner ("Bird Photography Portfolio — Kees Leemeijer / Munich '72 spirited inheritance · hand-crafted") followed by the Grid section. There is no section index, no runtime/specimen split pointer, no banner-comment style guide, no edit rules beyond the single line at L13 ("Edit only this block to retune the system"). The file is 1591 lines; an editor opening it cold gets oriented only by scrolling.
- **Why it matters:** Per spec §3 axis-2 file-preamble criteria — a 1591-line single-file specimen should answer in 10–30 lines: (1) what the file is; (2) what lives in it, in order; (3) how to navigate (the runtime/specimen split, the banner-comment style); (4) edit rules.

- **See also:** R-1 (preamble references `@layer`), R-7 (preamble's section index updates after reorder).

#### R-3 · Mono font stack repeated 38 times; extract `--mono-stack` token

- **Axis:** §1 (Token discipline)
- **Location:** Throughout `style.css` — 38 occurrences of `font-family: ui-monospace, "SF Mono", Menlo, Consolas, monospace;`. Two callsites use a SHORT variant without "Consolas": `style.css:186` (`.photo .placeholder::after`) and `style.css:329` (`.compass`).
- **Observation:** The stack appears in many specimen rules and a few runtime rules. The `--font-stack` token at L62 covers `'ABC Diatype'` only; there's no `--mono-stack`. The two short-variant callsites are a divergence — either intentional (no documented reason) or a missed update when the long stack expanded to five fonts.
- **Why it matters:** Single-source-of-truth violation. Adding a stack member or fixing a typo across 38 callsites is error-prone. The short variant is silent drift between two stacks that should agree.
- **Recommendation:** Define `--mono-stack: ui-monospace, "SF Mono", Menlo, Consolas, monospace;` next to `--font-stack` in the `:root` palette block. Replace all 38 callsites. Audit the two short-variant callsites and align (no documented reason to drop "Consolas").
- **See also:** R-1 (a `:where(.sr-mono, …)` reset in `@layer specimen` becomes feasible too, but the token is the cleaner expression of intent).

#### R-4 · Charcoal alpha ladder duplicated as 34 hex literals; derive via `color-mix()`

- **Axis:** §1 (Token discipline)
- **Location:** 34 occurrences of `rgba(26, 26, 26, X)` throughout `style.css`. The HTML §1.4 alpha-ladder (`index.html:210–217`) catalogues the documented charcoal-alpha roles: `0.04 subtle bg fill`, `0.06 hairline border`, `0.10 section rule`, `0.65 utility text — AA`, `0.70 body text — AA`, `0.75 legend body`. CSS uses these PLUS undocumented `0.12` (checker pattern, grid-anatomy border), `0.45` (overlay center label), and `0.60` (utility text variant).
- **Observation:** The HTML specimen documents "Charcoal alpha ladder" as a discrete brand system with named roles. The CSS implements those roles as 34 secondary copies of the `--charcoal` rgb. If `--charcoal` ever changes (it shouldn't — it's a locked identity token), every literal silently goes out of sync. The undocumented values (0.12, 0.45, 0.60) are quiet ladder-extension drift.
- **Why it matters:** Token discipline. The system claims a single source of truth for charcoal; the implementation has 34 secondary sources.
- **Recommendation:** Replace `rgba(26, 26, 26, A)` with `color-mix(in srgb, var(--charcoal) (A·100)%, transparent)` at every callsite. `color-mix()` is Baseline Widely Available since 2023. Consider also: align the alpha-ladder spec (HTML §1.4) to include the undocumented rungs (0.12, 0.45, 0.60), or remove their CSS uses.
- **See also:** R-5 (blue alpha ladder, same pattern), R-10 (field alpha values), §7 (this *is* a modern-CSS finding led from §1).

#### R-5 · Blue alpha ladder duplicated as 10 hex literals; derive via `color-mix()`

- **See also:** R-4.

#### R-7 · Specimen-block source order doesn't match HTML render order

- **Axis:** §2 (File organization & narrative)
- **Location:** `style.css:692–1591` (specimen section as a whole)
- **Observation:** HTML renders sections in canonical order: 00 → 1.1 → 1.2 → 1.3 → 1.4 → 1.5 → 1.6 → 1.7 → 1.8 → 2.1 … 2.6 → 3.1 → 99. CSS authors them as: Masthead (00) → Principles (1.1) → Color (1.4) → Photo treatment (1.4) → Typography (1.5) → Spacing (1.6) → Motion (1.8) → Mobile-cell (2.6) → Elevation (1.7) → Colophon (99) → Grid (1.3) → Identity (1.2) → Anatomy template → Overlays (3.1). This is roughly the author's working order, not a logical sequence.
- **Why it matters:** Navigation. Finding a section's CSS requires either grepping or scrolling. With consistent ordering, "section 1.3" lives in a predictable place.
- **Recommendation:** Reorder specimen-block clusters to match HTML render order. Move §1.2 Identity (currently L1284–1373) and §1.3 Grid ruleset (currently L1130–1190) to follow §1.1 Principles. Move §1.7 Elevation (currently L1054–1107) into the §1.x sequence. The anatomy template (L1375–1434) is a cross-cutting primitive shared by all 2.x components; place it just before §2.1 (the first component that uses it). The `?grid` debug overlay (L1192–1239) and Below-1336 fallback (L1241–1282) are utility blocks; keep them at the end of the specimen section, adjacent to each other. With `@layer specimen` (R-1) wrapping the block, the reorder is purely cosmetic — no specificity risk.
- **See also:** C-3 (the stale "first specimen" banner sources from this disorder), R-1 (layers make the reorder safe), R-2 (preamble's section index reflects the new order).

#### R-8 · Sub-elements `.ind-dot`, `.live`, `.overlay--backdrop` lack the `sr-` prefix in specimen scope

- **Axis:** §3 (Naming conventions)
- **Location:** `style.css:1504` (`.ind-dot`), `1568` (`.live`), `1586` (`.overlay--backdrop`). HTML usages: `index.html:747` (`.ind-dot`), `764` (`.live`), `773` (caption text mentions `.overlay--backdrop`). Note: `.overlay--backdrop` is documented as an opt-in modifier but never applied to a class attribute in HTML.
- **Observation:** All three are scoped under `.sr-overlay-*` blocks but break the `sr-` prefix discipline. Per spec §1 axis-3 column, "BEM `block__element--modifier` uniformity"; per the same row's example, "a class using `sr-foo-bar` where BEM convention says `sr-foo__bar`."
- **Recommendation:** Rename:
  - `.ind-dot` → `.sr-overlay-primitive__dot` (it's a child of `.sr-overlay-primitive__sample`)
  - `.live` → `.sr-overlay-applied__layer__live` (or `__pulse`, if the role is to indicate liveness more than position)
  - `.overlay--backdrop` → `.sr-overlay-applied__layer--backdrop` (it's a modifier on the layer, so the BEM should reflect that)
  - HTML at the cited lines updates to match. The §3.1 caption text at `index.html:773` that demonstrates the modifier name updates too.
- **See also:** R-9 (the bare `.dot` is a parallel issue; different choice may apply because `.dot` is a runtime atom).

#### R-9 · `.dot { color: var(--blue); }` duplicated as 6 redundant scoped rules

- **Axis:** §5 (Dead code & duplication)
- **Location:** Six rules of the form `.<ancestor> .dot { color: var(--blue); }` at `style.css:280` (`.identity`), `709` (`.sr-masthead__wordmark`), `1128` (`.sr-colophon__signature`), `1306` (`.sr-identity-mark__wordmark`), `1325` (`.sr-identity-clearspace`), `1358` (`.sr-identity-min__wordmark`).

#### R-12 · `width: 100% !important;` on the below-1336 fallback is the file's only `!important`

- **Axis:** §4 (Specificity & cascade hygiene)
- **Location:** `style.css:1270`
- **Observation:** Inside the 1335px fallback, `.sr-cell, [class*="sr-cell--"]` sets `display: block; width: 100% !important; margin-bottom: var(--gutter);`.
